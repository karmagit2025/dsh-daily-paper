# UP 日报（dsh-daily-paper）

两处入口，同一页内容：

- **左侧导航栏**的一项「UP 日报」，点开在主区域显示报纸；
- **设置** 里同样一项，方便和别的插件一起管。

页内两个页签：「报纸」看当天收集到的东西，「配置」管 B站账号和关注的 UP 主。

## 报纸

- 一天一期，按信源分栏（目前是 B站，后面的小红书/即刻各占一栏）。
- 每条给标题、UP 主、时长、要点、可执行项和跳转链接；需要点开原视频就直接点标题。
- 顶部可以「较新 / 较早」回翻往期，「刷新」重新读一次磁盘。
- 一期就是一个 JSON：`~/.dsh/daily-paper/issues/<YYYY-MM-DD>.json`。只有
  `sections[].items[].title` 是必需字段，其余缺失就不渲染对应部分。

```json
{
  "date": "2026-11-14",
  "lead": "一句话导语",
  "sections": [
    { "source": "bilibili", "label": "B站",
      "items": [{ "title": "…", "author": "UP主", "url": "https://…",
                  "duration": "03:36", "summary": ["要点"], "todo": ["可执行项"] }] }
  ]
}
```

## 配置

页面里的改动写到 `~/.dsh/daily-paper/config.json`，每天 09:00 的采集任务读它：

- **开关**：关掉就不再采集、不再出新的一期。
- **B站账号**：`SESSDATA`、`bili_jct`、`DedeUserID` 三个 Cookie 字段。B站没有免登录的
  关注流接口，拿不到登录态就只能看到公开简介。
- **关注的 UP 主**：一行一个 uid + 备注名 + 分类（财经 / AI 工具 / 其他）。
  uid 是 B站空间页 `space.bilibili.com/<uid>` 里那串数字。
- **采集参数**：每个 UP 主取最近几条、回看几天。

Cookie 只存在本机这个 JSON 里，接口也只在 `127.0.0.1` 上；但它确实会出现在
浏览器页面的输入框里，公用电脑上注意别开着配置页走开。

## 谁写报纸

插件自己不抓数据。采集由一个每天的定时任务完成：抓 B站 → 字幕/转录 → 摘要 →
把当期 JSON 写进 `issues/`，同时用飞书机器人推一份。所以：

- 想立刻看到更新，手动跑一次那个任务即可，不用重启应用。
- 加一个新信源（小红书、即刻…）时，只要让采集端往同一份 JSON 的 `sections`
  里多写一栏，这个页面不用改。
- 同一日期重复写会整期覆盖，不做合并。

## 已知限制

- 左侧入口默认固定；若被「取消固定」，会落进左侧栏的「更多」菜单，重新固定即可。
- 纯文本渲染：`summary` / `todo` 里写 Markdown 不会被解析。
- 配置保存走 `/api/daily-paper/config`，同一时间只有一个写入方；并发保存以后写的为准。
